# FastValue guide

The full reference: every tab, agent, study and setting. The short version is the [README](../README.md).

A fast decision desk for your stock portfolio, built around a value investor's framework and hosted locally. It works in three steps:

1. **Add your portfolio.** Enter your positions (shares, average cost, date opened) and your cash, or import your broker's transaction export (Trade Republic natively, any other broker through the CSV template), which fills them in EUR and keeps your whole trading history for the track record. The review starts with what to do now: one list grouped by action (Exit, Trim, Look at, Add), one sentence of why per holding and the evidence one click away; holdings that need nothing are folded away. Funds, metals and derivatives are checked as what they are, not as companies. Any other ticker gets an entry verdict (ENTER, ENTER STAGED, WATCH or AVOID) with a position size.
2. **Decide what matters to you.** The weights set how much each side of the analysis counts: valuation and returns on capital (Fundamentals), how management treats shareholders (Shareholders), the company against its peers, suppliers and customers (Competitive Position), insider trades, and the timing signals (trend, volume, options, macro regime, pullback). Owner weights change the decision. Timing weights change only the entry read. A live preview re-scores the last analysis before you save.
3. **Check it against the alternatives.** The Backtest tab replays your setup month by month on your portfolio (with its allocation) or on one ticker, point in time since 2011, against buy and hold of the same allocation, the market and the classic strategies. A batch search tries many setups at once and ranks them by their weaker half of the period, so a setup has to win in both halves to rank high.

Fundamentals go first. An **owner score** from the Fundamentals and Shareholders agents is the verdict on a 12-month horizon: a number from -100 to +100, shown with the scored rules behind it, never as a BUY, HOLD or SELL label (D-45). Two levels set in the Weights tab, the **entry level** (+15) and the **exit level** (-15), turn the score into actions in the portfolio review, the alerts and the backtest. The other agents form **entry timing** (the "timing panel" in the code): signals from price and the market (trend, pullbacks, volume, options activity, the market regime and the VIX) that say whether now is a good moment to buy, whether to stage the purchase and how much to buy. It never votes. You can trace every point of every score back to the rule and data that produced it.

Decision support only. Not financial advice.

Codes such as D-45 or T-05 point to entries of the decision log, and the study numbers are kept with it: both stay private.

## Quick start

```bash
python -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"

python web/app.py                          # dashboard at http://127.0.0.1:8501
python -m core.runner --multi-agent --ticker AAPL          # owner decision + timing panel
python -m core.runner --watchlist AAPL MSFT NVDA
python -m core.runner --ticker AAPL --portfolio-add 10 150.25 --opened 2026-01-15
python -m core.runner --cash 20000 --portfolio              # review every position
python -m core.runner --candidate --ticker KO               # should I enter? (or the risk, if held)
python -m core.runner --score-backtest --ticker SPY --frequency weekly   # entry timing only
python -m core.track_record --csv ~/Downloads/transactions_<from>_<to>.csv   # import + track record report
python -m core.monitor                     # daily check: review + watchlist, history, alerts on changes
python -m core.monitor --install           # schedule it on weekdays after the US close (macOS launchd)
python -m core.sentiment_validation        # does the stored news tone predict returns yet? (D-26)
pytest                                     # offline: network is blocked in tests

# Point-in-time test of the value agents on the historical S&P 500 (SEC data, 2011+)
export SEC_USER_AGENT="fastvalue you@example.com"
python -m core.value_study                 # report: analysis/output/value_study.json
```

`FASTVALUE_PORT` changes the port. `FASTVALUE_DEBUG=1` enables Flask debug mode (localhost only; never expose it). The older `QUANT_PORT` and `QUANT_DEBUG` names still work.

## How a decision is built

1. **Fresh data.** `data/fetcher.fetch_live_ohlcv` loads cached history and refreshes the latest month, including today's forming bar while the market is open. The result carries a freshness status: `LIVE` (intraday), `CLOSE` (last completed session) or `STALE` (sessions missing). Sessions follow the listing's own exchange (`data/exchange_calendar.py`: time zone, hours and holidays for New York, Toronto and the main European exchanges), so a holiday is not stale and a bar still forming in Frankfurt is never cached as complete.
2. **Agents run in parallel.** Each returns a score (-100..100), a confidence, a data quality (`LIVE`, `PARTIAL`, `UNAVAILABLE`), key factors, a `score_breakdown` with signed points per rule, and optional price levels. A failing or slow agent is excluded instead of breaking the analysis.
3. **No invented data.** When a provider has nothing, the agent returns `UNAVAILABLE` and is excluded from its layer. The UI shows it, and confidence drops when coverage is thin.
4. **Two layers** (`agents/scoring.py`, shared by live analysis, the weights preview, the watchlist, the portfolio review and the backtester). Each agent has a `role`. The roles below are the shipped defaults. In the Weights tab you can move any agent to Decides, Timing or Informative (shown with its evidence, scored in neither layer), stored as `roles` in the weights config (D-21):
   - **Owner score (decides).** Agents with `role = "owner"`: Fundamentals (45%), Shareholders (55%), Competitive Position and Insider (0%, evidence only). Weighted with `owner_weights`, independent of the market regime. Its thresholds give the internal band: STRONG_BUY, BUY, HOLD, SELL, STRONG_SELL on a 12-month horizon. The app never shows these codes (D-45): BUY reads "at or above the entry level" (`owner_thresholds.buy`), SELL "at or below the exit level" (`sell`), HOLD "between the levels"; the strong levels group the score backtest's rows and raise a watchlist alert when crossed. The codes remain in the API, the stored history, the command line and the studies, and the rules below use them. When no owner agent has data (funds, indexes, missing statements), or the company is a utility or a REIT (outside the framework, owner's call T-12), the ticker is **NOT_RATED**. Margin of safety: a BUY is capped at HOLD when EV/FCF is at or above `owner_max_ev_to_fcf` (35x by default, blank to disable in the Weights tab) or FCF is negative; financials are exempt. A well-run business can still be too expensive to buy.
   - **Timing panel (no vote).** Agents with `role = "timing"`: Momentum, Volume, Options, Macro, Pullback (15%), Sentiment (0%). The Macro agent's regime (BULL, CORRECTION, BEAR, CRISIS) selects the weight profile. Summarized internally as FAVORABLE / NEUTRAL / UNFAVORABLE (the app shows the timing score and its points instead), with the trend (50/200-day structure), the pullback setup, 12-1 month momentum, event risk from options and the VIX. It informs when to enter, how to stage and how much. The label is never a hold or exit rule: on the 2011-2026 panel it had no signal and flipped with small weight changes, while the pullback setup was the reading that predicted the next month.
   - Inside a layer: each raw score is normalized with `tanh(score / scale) * 100`; effective weight = weight x (floor + (1 - floor) x confidence); composite = weighted mean. Strongly opposed agents raise a conflict warning and dispersion lowers confidence.
   - Why: in the point-in-time value study (below) the value agents picked stocks better than the market while the trading signals lost money over 20 years and, as a filter on value picks, cost 0.9% a year. See `decision_log.md` D-11.
5. **Risk reference.** 2x ATR14 below the price (wider when options price an event), bounded by the 20-day swing low, with a 2R target for BUYs. It is a sizing aid, not an automatic exit: the owner score is re-rated yearly after the 10-K, and tight stops hurt mean-reverting value holdings.

## Portfolio review

`data/portfolio.py` stores positions in `data/store/portfolio.json` (git-ignored). `core/portfolio.py` reviews them:

- **Per position**: its class, owner decision and score now versus at entry (the snapshot stored when the position was added, or the rating replayed for the month you bought; a rating taken more than a month after the purchase is not compared, because it says nothing about the thesis at entry), the owner agents' biggest concerns, unrealized P&L, weight, drawdown from the high since entry, distance to the ATR stop reference (a sizing reference), days needed to exit at 10% of the daily volume, setup and your notes.
- **Classes** (D-35): core funds (broad index, bond and money-market funds, the style view's Core bucket), other funds (sector and theme funds, or a fund whose look-through is more than 60% one sector), stocks, metals and commodities (physical metal ETCs, crypto trackers), derivatives, and holdings without a price. The owner score is a framework for companies, so it decides only for stocks:
  - Stocks: EXIT (owner SELL or a reverse-split red flag), TRIM (above the position cap), REVIEW (owner data thin, no statements, owner score fell 20+ points to HOLD since a rating from within a month of the purchase, or a fall from the high past 25% or the holding's own usual yearly swing if larger, only in the HOLD band), ADD (owner BUY, below the 10% initial size, cash available and a pullback inside an uptrend), else HOLD. A BUY below the starting size with cash but no pullback shows as "room to add", information and not an action. Utilities and REITs (T-12) stay HOLD outside the framework. An owner score in the HOLD band keeps a position (exit only on SELL): a buy/hold band keeps turnover low, which is where value strategies keep their edge after costs. Deeper and confirmed exit levels were tested (`core/exit_rule_study.py`, T-14) and made no measurable difference, so the SELL level stays.
  - Core funds: HOLD, no owner REVIEW, no position cap (a broad fund is not one company); checked on cost (a look above 0.30% a year), overlap with another core fund (weekly correlation of 0.95 or more over two years), the plan, and the price source of an import.
  - Other funds and metals: the same 20% cap as a company, nothing else from the owner score.
  - Derivatives and holdings without a price: counted at cost under "Needs a price"; derivatives are checked against your yearly budget.
- **Your plan**: a core share and a yearly derivatives budget, stored in `data/store/portfolio.json`. Drift is flagged beyond 5 points or a fifth of the target, whichever is larger; the split of what you have invested (core, satellite, metals, speculative) is always shown. The review never changes a company's BUY, HOLD or SELL; the EXIT, TRIM and ADD thresholds are those of D-12 and T-14, and two replays are still pending (the ADD gate and a 10% cap, `next_steps.md`).
- **Portfolio**: total and invested value (holdings without prices counted at cost), cash share, effective number of positions over single names and non-core funds (1 / Herfindahl), largest single holding, and the share of the portfolio in owner BUY, SELL and not-rated stocks. Every alert comes with what to do about it.
- **Analytics** (`core/portfolio_analytics.py`, D-24), shown as five sections of the review (Overview, Holdings, Risk, Winners & losers, Cycle & news). Everything is in the portfolio's currency on one calendar; risk uses weekly returns over two years, because daily returns understate how European and US holdings move together (they react to the same news on different days):
  - Allocation by holding, sector (funds looked through), cyclical / sensitive / defensive, industry, country, region, asset type and price currency, each with its share of risk and, for sectors, the gap to MSCI World.
  - Risk: each holding's share of risk against its share of value, volatility, beta and correlation with the rest; diversification ratio, tracking error, bad month, worst month and drawdowns of today's mix; a correlation heatmap and the pairs that move as one.
  - Performance: today's holdings at today's weights (cash left out) against MSCI World, the S&P 500 and the Nasdaq 100 (1 month to 5 years); for an imported account, your invested part's actual time-weighted line, and the whole account with its cash behind a legend click.
  - Winners and losers since you bought (dividends included for imported holdings) and over 1 month to 1 year, without counting money you added as gain; the P&L of foreign holdings split into the share price's move and the currency's move.
  - Cycle and news: the Macro agent's backdrop, your sector groups against the benchmark, news tone with the headlines behind it, the owner score against 30 and 90 days ago, earnings soon. Context only: the owner score still decides.
  - Deep links: `#portfolio=review/risk` (or `overview`, `holdings`, `movers`, `cycle`).
- **Candidate** (`assess_candidate`): ENTER, ENTER_STAGED (VIX at or above 40, price extended, trend broken, event near or 12-1 momentum deeply negative), WATCH (owner HOLD), AVOID (owner SELL) or NOT_RATED. The size is the smallest of: 1% of the portfolio at risk between entry and the ATR stop reference, the 10% new-position cap, available cash, and what 5 days at 10% of daily volume can absorb. Limits are in `config/settings.py`. "How it fits" shows its correlation with your portfolio, the most similar holdings, portfolio volatility before and after adding it, and the overlap in sector and currency.

### Investing framework

The fundamentals, shareholder and macro agents follow a value approach. All formulas are in `analysis/fundamental_metrics.py`, and each input is shown in the agent's evidence table.

| Metric | Definition | Reference level |
|---|---|---|
| FCF | Reported FCF (operating cash flow - CapEx) feeds EV/FCF by default (`FCF_DEFINITION = "standard"`, owner's call T-05: it was the only variant with a return spread on the 2011-2026 panel, +4.0% a year top minus bottom quintile, and it is available for more companies). The owner formula, EBITDA - maintenance CapEx (D&A, capped at CapEx) - interest - taxes - change in working capital, with the working-capital change averaged over the last 3 yearly changes (`WORKING_CAPITAL_AVERAGE_YEARS`), and the same after all CapEx are always computed and shown next to it in the evidence table; `FCF_DEFINITION` can switch back to `owner` or `owner_all_capex` | |
| Working capital | Inventories + accounts receivable - accounts payable | |
| Market cap | Shares outstanding x live price | |
| EV | Market cap + debt (incl. leases) - cash and short-term investments | EV well above market cap means heavy debt |
| EV/FCF | Primary valuation ratio (not for financials) | Market average 16-17x, lower is cheaper |
| PER, PER ex-cash | Market cap / net income; ex-cash subtracts net cash | Market average 16x |
| ROIC | EBIT x (1 - T) / (equity + financial debt + leases - short-term investments) | Market average 13-14%; at or above 15% in every year of a 10-year history signals a durable moat |
| Reinvestment rate | (CapEx - D&A + acquisitions) / FCF | Reported, not scored: it scored backwards in the 2011-2026 test and the asset-growth literature agrees. Heavy reinvestment at a ROIC below 8% still costs points |
| Net dilution cost | (Stock-based compensation - buybacks) / market cap | Scored: negative (buybacks exceed stock pay) is rewarded, above +1.5% of market cap penalized. Gross stock pay / revenue is shown as information |
| Share count trend | Diluted average shares, change per year over the available history | The strongest single metric in the test: below -1% a year (cannibal) rewarded, above +1% penalized |
| ROE, ROA | Net income / equity, net income / total assets | Used for banks and insurers |
| VIX | Long-run average 20 | At or above 40 is extreme fear: a buying opportunity (+6 points; 30-40 earns nothing, as 12-month returns after a first close above 30 were below average). Deploy in 2-3 tranches over 2-4 weeks |

Red flags: reverse splits in the last 10 years, dilution above 3% a year, stock pay above 6% of revenue (shown), and average daily dollar volume below $5M (forced-selling risk; also raised as a warning by the master agent).

Set `VIX_STANCE = "risk"` in `config/settings.py` to treat high VIX as a reason to avoid stocks instead. Either way, the regime (which picks the timing weight profile) still classifies high VIX as CRISIS, which shifts the timing panel's weight toward the macro agent; the owner score does not depend on the regime (D-11). The regime study (D-38) found the label orders market risk but does not predict returns, and the four profiles do no better than one.

News with sentiment attached: set `ALPHAVANTAGE_API_KEY` (free key, 25 requests a day; each item carries a sentiment score and a relevance score for the ticker) and/or `FINNHUB_API_KEY` (free key, 60 requests a minute; headlines scored with the lexicon). Keys are read from the environment only. The agent stays at weight 0 in the timing panel until the stored daily snapshots give enough history to test it; a daily `--portfolio` or `--watchlist` run builds that history.

True IV rank needs IV history, which Yahoo does not provide. The options agent saves one ATM IV snapshot per ticker per day to `data/store/iv_history/`. After 20 snapshots it switches from an HV-based proxy to a real IV rank, so a daily watchlist scan builds this up.

| `python -m core.systematic` | Trend, momentum and dip rules (200-day, the two-engine rule, PB EMA channel, 12-1 and MSCI momentum, RSI(2) dip, a fall from the high) on any market, as is or as a synthetic 2x or 3x fund spliced onto a real one (`--leverage 3 --vehicle TQQQ --extend`), with both halves, nearby settings, walk-forward and a block bootstrap; `--study savings` (invest each saving at once or wait for a dip), `--study rotation` (MSCI momentum across sector or country funds), `--study check` (today's trend state) | printed; `--json` writes `analysis/output/systematic_*.json` |
| Backtest tab (`core/lab.py`) | Your setup on your portfolio or one ticker, and the batch setup search (below) | in the dashboard |

## Backtest lab (`core/lab.py`)

The Backtest tab's Compare and Find-the-best-setup modes. Two stages keep it fast:

1. **Score panel, cached.** Every agent that can be replayed point in time is scored at each month-end since January 2011 for each ticker: Fundamentals and Shareholders from the 10-K facts filed by that date (the value study's scorer), Momentum, Volume and Pullback from the prices that traded, and the Macro agent once per date. Insider, Options and News Sentiment have no point-in-time history here and are left out (a note says so when your setup gives them weight). Scores are cached per ticker in `data/cache/lab/<hash of the agent code>/`, so a code change rescores instead of serving stale numbers. A new ticker takes a few seconds; a 9-holding portfolio scored from scratch in about 8 seconds on 6 processes.
2. **Setups, fast.** Your roles, owner weights, thresholds and safety cap are applied to the stored scores with the arithmetic of `agents/scoring.py`; `tests/test_lab.py` checks the decisions against `aggregate_layers` on random data. A search of 768 setups on a 9-holding portfolio takes about 6 seconds.

Trading rules (the portfolio review's): each holding has a slot sized by its allocation weight (current market value or equal weight). A slot buys on BUY or better, goes to cash on SELL or worse, and HOLD keeps what it was doing; holdings the framework does not rate (funds, utilities, REITs, no filings yet) stay invested. Optional entry gate from the timing panel. Start invested (you hold it today) or in cash. Cash earns 3-month T-bills, slots are rebalanced to the target weights yearly (April), quarterly, monthly or never, and every trade costs 10 bps by default. Decisions use month-end data and trade at that close, as in the value study. The classic strategies run inside each holding's slot on daily prices, with the same costs and cash rate.

Overfitting guard, fixed before any run (the owner's rule: data based, no tuning on noise): every result is also reported for the first and second half of the period. The search ranks setups by their weaker half against buy and hold, groups setups that traded identically, and reports the rank correlation between the halves and how the first-half winner did in the second half against your saved setup. Its verdict says to keep your setup unless a change wins in both halves. The holdings are the ones you own today, which flatters every strategy that holds them (survivorship); compare strategies with each other more than with the market. Owner scores need `SEC_USER_AGENT` to download filings; without it the cached filings are used.

## Trend and dips (`core/systematic.py`)

The Backtest tab's Trend and dips mode, for the question "can a rule step aside in deep falls, and is it worth it?" (decision_log.md D-48). Three studies:

- **A trend or dip rule** on one market: held in that market, in a synthetic 2x or 3x version (daily rebalanced: the multiple of the day's return, less borrowing at T-bills plus 0.5% and a 0.95% yearly fee), or in a real fund such as TQQQ from its first day, with the synthetic series before it and a check of how closely the two agreed. The history can be extended with the price index (QQQ with ^NDX to 1985, SPY with ^GSPC to 1927; no dividends there, and the result says how much that flatters a rule that sits in cash). The rule reads the close and trades at the next close; cash earns T-bills; every change of position pays the cost.
- **Saving into dips**: the same monthly saving invested at once, or kept in T-bills until the market is a set share below its high, over the whole period, each half and every 10-year window.
- **Momentum rotation**: MSCI's momentum method across the nine sector SPDRs or 13 country funds, against holding them all equally.

Every rule result carries the checks a backtest needs before it is trusted: both halves; the rule at each nearby setting (a rule that works at one setting only is fitted to the past); walk-forward (each year the setting with the best Sharpe over the previous five years, held for that year); and 1,000 reshuffles of the same days in blocks of about 20, paired with holding. The verdict calls a rule robust only with a smaller worst fall and a better Sharpe than holding in both halves and at most of its nearby settings.

The first card of the mode is today's state of the 200-day, two-engine and PB EMA rules on SPY, QQQ and IWDA.L; the daily check alerts when the two-engine rule flips (`TREND_WATCH`, `TREND_CHECK_RULES` and `TREND_ALERT_RULES` in `config/settings.py`). The rules are also in the strategy registry, so they run in Classic strategy and as rows of Compare. Nothing here changes a score or a weight.

## Point-in-time value study (SEC EDGAR)

Yahoo serves today's statements for the last four years, so the value agents cannot be replayed with it. `core/value_study.py` rebuilds what an investor could have known on each month-end since 2011 and runs the unchanged agents on it:

- **Universe**: S&P 500 members on each date (historical membership list), limited to companies with SEC filings and Yahoo prices. Companies that were later acquired or went bankrupt are mostly missing (coverage is about half the index in 2011 and all of it today), so the study also reports RSP, the equal-weight S&P 500 ETF, which has no survivorship bias.
- **Statements**: `data/sec_edgar.py` reads the SEC companyfacts API and maps us-gaap tags to the line items the metrics use. Only 10-K facts filed on or before the date count, and a restated figure replaces the original only from the restatement's filing date. Share counts are restated for splits.
- **Prices**: `data/price_history.py` keeps split and dividend data, so market cap uses the price that actually traded on the date and returns include dividends.
- **Insiders**: `data/sec_insider.py` reads the SEC's quarterly Form 3/4/5 data sets (each filing carries its filing date) and feeds the Insider agent the trades that were public on the date.
- **Output**: portfolios (top and bottom 20% by each agent and composite, monthly or yearly rebalancing, 10 bps per trade), rank information coefficients 1 and 12 months ahead, a test of every metric of the framework on its own, the market's valuation level by year, and a VIX > 40 event study.
- **What it changed**: the two-layer decision (owner score decides), the shareholder side weighted above valuation, net dilution scored instead of gross stock pay, reinvestment made informational, insider weight 0, the VIX rule at 40 only, and 10-year ROIC persistence.

**Competitive position study** (`core/competitive_study.py`): replays the Competitive Position agent's eight scored rules (the same functions the live agent runs) from the 10-K facts known on each month-end, with peers from the SEC industry code among that month's members (Yahoo industry membership has no history). The acceptance test was written before the first run (D-34): the 12-month rank IC, the top-minus-bottom quintile spread and the partial IC given the owner score must be positive over the whole period and in each half (t of at least 2 for the two ICs), and a 0, 10% or 20% blend must beat 0 in both halves; otherwise the weight stays 0. Result (October 2026): all four checks failed (12-month IC +0.008, t 0.4; partial IC -0.014; the 10% blend behind in both halves), so the weight is 0. The 10-K text notes are not replayed (it would need every historical 10-K). Run `SEC_USER_AGENT="app you@example.com" python -m core.competitive_study` (about 5 to 7 minutes the first time, `--rebuild`, `--limit N`, `--yahoo-industries` as options); the report is `analysis/output/competitive_study.json`.

The SEC requires a contact email in the User-Agent header of every request (fair-access policy). Set it in `SEC_USER_AGENT`; it is sent only to sec.gov and is not stored in the repository. Downloads are cached under `data/cache/` (about 50 MB).

## Adding an agent

Create `agents/my_signal_agent.py`. Any module ending in `_agent.py` is discovered automatically:

```python
from agents.base import BaseAgent, iso_date
from agents.registry import register_agent


@register_agent
class MySignalAgent(BaseAgent):
    key = "my_signal"            # stable id used in weights and the API
    name = "My Signal Agent"
    description = "One sentence shown in the Weights tab."
    category = "Technical"       # Technical, Flow, Fundamental, Sentiment or Macro
    role = "timing"              # "timing" (informs, no vote) or "owner" (part of the decision)
    score_scale = 45.0           # raw score where the normalized score reaches ~76
    default_weight = 0.0         # start informational; raise it once the backtest supports it
    point_in_time = True         # True only if evaluate() uses nothing but the OHLCV passed in

    def evaluate(self, ticker, ohlcv):
        if len(ohlcv) < 60:
            return self.unavailable("Need at least 60 bars")
        points = 10.0 if ohlcv["close"].iloc[-1] > ohlcv["close"].tail(50).mean() else -10.0
        return self.assessment(
            score=points,
            confidence=60,
            summary="Price vs 50-day mean.",
            raw_data={"score_breakdown": [{"factor": "Close vs 50-day mean", "points": points}]},
            data_as_of=iso_date(ohlcv.index[-1]),
        )
```

It then appears in the Analyze, Watchlist and Weights tabs (and the Backtest tab's daily timing mode if `point_in_time`; the monthly lab replays only the agents listed in `core/lab.py` `AGENT_COLUMNS`). A timing agent missing from a regime profile uses `default_weight`; an owner agent missing from `owner_weights` uses `default_weight` and is 0 in every regime profile. Put network access in a `data/` provider: wrap crumb-authenticated Yahoo calls in `data.yahoo.yahoo_call` (it retries, and raises when yfinance only logs a refusal such as 401 Invalid Crumb instead of returning its empty result), cache them with `data.cache_utils.ttl_cache`, and raise on failure so errors are not cached.

## Broker import and track record

**Benchmarks.** `PORTFOLIO_BENCHMARKS` in `config/settings.py`, primary first: MSCI World (IWDA), S&P 500 (CSPX) and Nasdaq 100 (CNDX), the accumulating iShares UCITS funds in London, converted to EUR at ECB rates. SPY and QQQ are not used: EU brokers do not sell them to private investors and their price leaves out the dividends. Risk figures, the sector comparison, each order's 90-day comparison and the rules lab's core fund use the primary alone (D-36). Click a legend entry in any line chart to hide or show its line; the choice is kept per chart in this browser, and one line always stays.

Import your broker's export in the Portfolio tab (choose the broker in the dropdown; the CLI `python -m core.track_record --csv <file>` takes a Trade Republic file). Trade Republic is parsed natively; any other broker goes through the FastValue CSV (`data/generic_ledger.py`: date, type, isin, name, shares, price, amount, fee, tax, currency, plus optional id, asset_class and plan; download the template from the dropdown's hint or `/api/brokers/template`; EUR accounts for now). A broker is one parser in `data/brokers.py`; nothing downstream changes. The file is read in memory and never stored:

- **Privacy.** The counterparty name and IBAN columns are dropped as each row is read, and so are the name, description, merchant and original-currency fields of transfers and card payments (they repeat your name, IBANs and where money was spent); any row without an ISIN keeps no name at all. Only the cleaned bookings are kept, in `data/store/broker_ledger.json` (git-ignored). Only ISINs and tickers are sent out, to look up prices.
- **Checks** (`data/trade_republic.py`, `core/ledger.py`): every field parses, ids are unique, the account is in EUR, trade amounts equal shares x price, signs are consistent, migration rows net to zero, no position goes below zero, cash (the sum of amount + fee + tax over every row) is not negative, and the cost per share the broker records in its migration rows matches the ledger (it is FIFO with buy fees and taxes included).
- **Ledger.** Events in time order: cash, shares, an average-cost basis and FIFO lots per ISIN, realised P&L both ways, round trips from the first buy to zero shares, dividends, fees and taxes. ISIN changes and temporary rights ISINs are folded into their stock. Owner's calls (D-23): stock perks are income; tax corrections keep their exported signs; shares delivered out were moved to another broker (a transfer, not a sale); private-market funds are left out (their payments count as money moved out).
- **Prices** (`data/instruments.py`, `data/fx.py`): each ISIN is matched to a Yahoo listing and checked against the prices you actually paid (the gap between the execution price and that day's trading range, in EUR at the ECB rate). Up to 3% fits; above 8% the listing is rejected and you set the ticker by hand in the import card. Prices stay in the listing's currency; the portfolio converts values to EUR.
- **Portfolio.** Open holdings with a price source replace the previously imported positions (positions you added by hand stay), with the broker's cost per share and the date the current holding started; cash comes from the ledger.
- **Track record** (`core/track_record.py`, Backtest tab, "My track record"): daily account value in EUR, time-weighted and money-weighted returns (a holding's money-weighted return is annualised only once its money was in for a year), Modified Dietz per year, the invested part against three indices, time-weighted and with the same buys and sales in each (public market equivalent), cash on its own (share, interest, its effect on the return, and every deposit into each index, split exactly into your choices and your cash), per-holding and per-round-trip results, and what-ifs: the sold shares kept, no turbos, and stop-loss, take-profit and minimum-holding rules on your actual entries (adopted only if they win in both halves with |t| of at least 2). Optionally FastValue's owner rating at each stock buy and its sell rule on your entries, replayed point in time with the saved weights; it also fills in the owner score at entry of imported positions. Learnings are ranked by confidence tier, then EUR impact; t statistics count orders in one name and month once. With a few dozen trades most patterns are low confidence, and the lesson then says to keep what you do. Nothing here changes the scoring. The full report with every order and round trip is written to `analysis/output/track_record.html` (git-ignored).
- **Your style, entries and exits, rules lab** (`core/style_profile.py`, `core/history_lab.py`; sections of My track record): style numbers from the ledger (holding periods, bets, pyramiding, hit rate, payoff, the positions that carry 80% of the gains, concentration today, cash, unrealised share, recurring against one-off dividends, core / satellite / metals / speculative); every buy tagged with the conditions at the time (distance from the 52-week high, trend, last month's move, RSI, the name's volatility class, kind of add, size, when in the build, open positions, the market's trend and drawdown, the VIX, the market regime the trading day before, the owner rating when replayed) and the tags ranked by the gap between their best and worst bucket 90 days later against MSCI World; exits (into weakness, steady names sold quickly, losers cut fast) with what the names did after; and the rules lab, which replays the whole account day by day under a rule (no turbos, skip small or all one-off buys, a weight cap with trims, minimum holding periods for all or only steady names, stop-loss, take-profit, idle cash into the core fund), with the same cash flows, prices and the account's typical fee. A rule is adopted only if it wins over the whole period and in each half alone with t of at least 2 across the names it changed; everything is in sample on one history, so a winner is a hypothesis to test forward. The engine's replay of the actual orders must match the account to the cent. Each run stores its verdicts per export in `data/store/rules_lab_history.json` (git-ignored, no amounts), and the table shows how many monthly imports in a row each rule was ahead in both halves (three makes it a candidate to write down, D-32).
- **Your history against the weights** (`core/weights_review.py`, the Entries & exits section): each entry tag is mapped to the agent that reads the same condition, with the direction that agent rewards; for every agent the card shows its weight today, what your buys say (rewarded against penalised buckets, both halves, confidence) and what the S&P 500 studies say (`config/panel_evidence.json`, market numbers only), with a verdict (in line, your history disagrees, mixed, too few cases, not testable). Then your buys by the market regime at entry, and a short list of what this suggests in today's regime, each labelled by its evidence (your history and the panel agree, the panel only, your history only). Nothing changes a weight; a weight question names the replay that would test it (D-39).
- **Share.** The Share button writes `analysis/output/my_style.html` (git-ignored): shares, counts, holding times and returns only, never an amount; instrument names only when ticked. It includes your buys by market regime; the agents, weights and suggestions stay on your machine. Nothing is sent anywhere.
- **Tests.** `tests/test_trade_republic.py` uses a synthetic export; `tests/test_brokers.py` covers the registry and the generic CSV; `tests/test_style_lab.py` the style profile, the rules lab and the shareable page; `tests/test_weights_review.py` the history against the weights. `tests/test_trade_republic_real.py` checks your real export against its specification only when `FASTVALUE_TR_CSV` points to it; the expected figures stay in `data/store/tr_expected.json` (git-ignored).

## Configuration and local state

- `config/agent_weights.json`: shipped defaults: owner weights and thresholds, timing weights per regime and thresholds, confidence floor (tracked in git).
- `config/panel_evidence.json`: the S&P 500 study numbers the track record compares your history with (market data only; update after a study rerun). `config/industry_sources.json`: the hand-checked outlook sources per Yahoo sector and industry, with the date they were checked.
- `data/store/` (git-ignored): your saved weights (`agent_weights.json`), score history (`history.db`, with owner and timing scores), watchlist, portfolio and your plan (`portfolio.json`), the daily check's state, alerts and log (`monitor_state.json`, `alerts.jsonl`, `monitor.log`), IV snapshots, the imported broker ledger (`broker_ledger.json`), the ISIN-to-ticker map (`instruments.json`) and the SEC contact email when you set it in the app (`local_settings.json`; the `SEC_USER_AGENT` environment variable takes precedence).
- `data/cache/` (git-ignored): Parquet OHLCV cache, SEC downloads (including `sec/margins_v1_*.parquet`, cost of revenue and gross profit) and ECB exchange rates (`fx/`). The Company card's SEC data sits in `sec/` too: quarterly extracts (`reports_v2_*`, a day), the filings index (`submissions_*`, `filings_v1_*`, a day) and the exhibit lists of results and Regulation FD 8-Ks (`exhibits_v1_*`, kept). `competitive/` holds the Competitive Position agent's peer cards, Yahoo industry lists and 10-K extracts (a few MB, a week for cards and lists, one file per filing for the 10-K). `regime_history/history.json` is the regime panel's replay (about 200 KB, a day).
- Social sentiment (D-43), all off by default and read from the environment only: `FASTVALUE_SOCIAL_SOURCES=stocktwits,reddit` turns the sources on; `REDDIT_CLIENT_ID` and `REDDIT_CLIENT_SECRET` (a personal "script" app; optional `REDDIT_USER_AGENT`) enable Reddit; `FASTVALUE_OLLAMA_MODEL` (for example `qwen3:4b`, optional `OLLAMA_HOST`) scores untagged posts with a local model; `FASTVALUE_SOCIAL_API_SCORER=1` together with `ANTHROPIC_API_KEY` allows an API model. Only the ticker leaves the machine, plus the public post text when the API scorer is on.
- `.gitignore` also keeps every CSV, spreadsheet, Parquet and database file and any `.env` out of git, so a broker export dropped into the folder by mistake is never committed.
- The dashboard listens on 127.0.0.1 only, answers only requests addressed to 127.0.0.1 or localhost, accepts changes only from its own page (same origin, including the port) and sends a Content Security Policy that allows scripts, styles and fonts from the app alone; the chart library and the Inter font are vendored in `web/static/vendor/`, so opening the page contacts no third party. A web page open in the same browser can neither read your portfolio nor change it.
- `config/settings.py`: cache TTLs, agent timeout, paths, `VIX_STANCE`, `FCF_DEFINITION`, `WORKING_CAPITAL_AVERAGE_YEARS`, and the portfolio limits (position cap 20% for a company, fund or commodity, none for core index funds; new position 10%; 1% risk per position; a look after a fall of 25%, or the holding's usual yearly swing if larger; 5 days to exit).
